# Intent: AI-generated case report PDF

Author: Minh Triet Nguyen · Date: 2026-11-15 · Status: accepted

## Problem
At the end of a review there is nothing to hand to a surgeon or a judge. The case, the defect, our annotations, the measurements and the conversation with the assistant all live inside the app. We want a printable case report like a commercial virtual-surgical-planning report (reference: Stryker / 3D Systems "VSP Cranial Demo Case Report"), generated by the assistant.

## Desired outcome
- In chat, the user asks for a case report ("make a case report for this defect"). The main Deep Agent spawns a **report subagent**. The thinking UI shows it spawning, each step (capturing views, writing sections, building the PDF) and returning the finished PDF.
- The PDF follows the reference layout, with our own branding:
  - **Cover page:** University of South Florida name and logo; case information table (project, case, sample/candidate, revision, date); three hero renders of the defect; a short case summary.
  - **Anatomy pages:** multi-view render grids of the skull (lateral left/right, frontal, top, posterior) with the defect and implant highlighted in colour.
  - **Annotated pages:** views that use our annotation tools (highlights, planes, ROIs, lines) with callout labels and measurements, captured from chosen camera views. Where useful, the three slice views (axial, sagittal, coronal) at the defect.
  - **Conversation and findings:** a summary of the assistant conversation for this case, measurements, and any research sources cited.
  - Footer on every page: USF logo, case id, page "n of N", "Demo, not for clinical use".
- The user can open or download the PDF from the chat.

## Affected users and systems
- Demo audience, surgeons reviewing a case, the team presenting.
- `backend/ai/` (report subagent, PDF building), chat streaming, viewport/slice capture in `app/src/viewport/` and `app/src/ui/SliceViewport.tsx`, annotation overlays, `AiChatPanel`.
- Depends on `ai-deep-agent-research` (Deep Agent and subagent thinking UI) and benefits from `annotation-color-system`.

## Constraints
- Built on the same Deep Agent as `ai-deep-agent-research`.
- No AI writes to application data (assistant spec R61). Highlights the agent adds for the report are temporary view overlays, not saved annotations, unless a human accepts them through the existing proposal flow.
- 3D renders and slice images come from the browser (WebGL). The server cannot render them alone.
- No Stryker, 3D Systems or VSP names, logos, legal text or surgeon agreement. We copy the layout idea only.
- Every page says it is a demo and not for clinical use.

## Out of scope
- Surgeon signatures, agreements, terms and conditions, ordering or manufacturing.
- Cutting/positioning guide design (pages 5–6 of the reference).
- Editing the PDF after it is generated (regenerate instead).

## Open questions
- USF logo: will you add the official logo file to the repo, and is using it OK under USF brand rules for a hackathon demo?
- Where does the PDF live: download only, or stored as an artifact on the case?
- Which conversation goes in: the current chat session only, or all chat for this case?
- Build the PDF on the server (Python `reportlab`) or in the browser? Leaning server, with images posted from the browser.
